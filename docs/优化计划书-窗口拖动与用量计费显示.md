# 优化计划书：窗口拖动 + 标题栏避让 + 用量计费显示

> 目标仓库：`dsh-desktop`（Electron 桌面壳 + 内嵌 `dsh web`）。本文档供另一个开发 agent 执行，逐项给出改动位置、机制与验收标准。所有结论均基于当前工作区实测源码（`@deepseek-ai/dsh@0.1.0-rc.6`）。

## 0. 架构速览（先读这节）

| 层 | 代码位置 | 角色 |
|---|---|---|
| 桌面壳（本仓库自有） | `src/main.ts` → 编译到 `lib/main.js` | 创建 BrowserWindow、注入拖拽 CSS、红绿灯位置、`dsh-desktop-platform` 查询参数 |
| Web 前端（第三方，`node_modules`） | `@deepseek-ai/dsh-client-ui-*` 各包 | React UI：侧边栏、会话 header、插槽系统 |
| 数据 | `@deepseek-ai/dsh-token-meter`、`dsh-session-projection`、`dsh-host-apiproxy` | token 用量投影、客户端推送、`/api` 网关 |
| 插件（本仓库最近已用） | `~/.dsh/profiles/web/node_modules/dsh-plugin-vision` | host+client 一体的插件范式，可直接抄结构 |

**关键机制**：
- 桌面壳通过 `window.webContents.insertCSS(DRAG_REGION_CSS)` 注入 CSS（`src/main.ts` 第 40–60、196 行）。`-webkit-app-region: drag` 只能在 Electron 渲染进程里生效。
- 桌面壳在 `src/main.ts` 第 192 行注入 `dsh-desktop-platform=<platform>` 查询参数，前端可据此判断「在桌面 App 内」还是「普通浏览器」。
- UI 插槽由 slot 渲染器输出 `data-slot="<slotKey>"`（已在 `dsh-client-web-react` 确认 `data-slot": slotKey`）。已知 slot key：`conversation.session.header`、`conversation.session.header.utilities`、`sidebar`、`sidebar.workspaces`、`sidebar.settings`、`sidebar.footer.action`。
- 构建：改 `src/*.ts` 后必须 `pnpm build`（tsc → `lib/`）；打包 App 用 `pnpm package`/`pnpm dist`；开发用 `pnpm dev`。

## 需求 1：左侧导航栏按住可拖动窗口

**现状**：`DRAG_REGION_CSS` 只让会话 header（`[data-slot="conversation.session.header"]`）和 hero 行可拖动，导航栏不可。

**改动**（仅 `src/main.ts` 的 `DRAG_REGION_CSS`，无需动 Web 包）：

```css
/* 追加：导航栏整体可拖 */
[data-slot="sidebar"] { -webkit-app-region: drag; }

/* 交互子元素必须恢复 no-drag，否则点击被拖拽吞掉 */
[data-slot="sidebar"] button,
[data-slot="sidebar"] a,
[data-slot="sidebar"] input,
[data-slot="sidebar"] select,
[data-slot="sidebar"] textarea,
[data-slot="sidebar"] [role="button"],
[data-slot="sidebar"] [tabindex],
[data-slot="sidebar.workspaces"] *,
[data-slot="sidebar.settings"] *,
[data-slot="sidebar.footer.action"] * { -webkit-app-region: no-drag; }
```

**注意/风险**：
1. `app-region: drag` 会吞掉元素上的鼠标事件。会话列表/工作区行的真实元素若既不是 `button/a/[role=button]` 也没有 `tabindex`（例如带 `onClick` 的 `<div>`），会被拖拽拦截导致「点不动」。**必须用 DevTools 核对 `[data-slot="sidebar"]` 下的真实 DOM**，把每个可点击行纳入 `no-drag`。必要时让选择器更保守：只对侧边栏的空白/wordmark/列背景加 drag，行元素一律 no-drag。
2. 同步扩展 `verifyDragRegions()`（`src/main.ts` 第 206–243 行）的探针，让它也报告 `sidebar` 的 drag 区域与 no-drag 控件数，便于启动时自检。
3. 只在桌面 App 生效即可（浏览器里 `app-region` 被忽略，无副作用），无需判断平台。

**验收**：按住导航栏空白处能拖动窗口；会话列表/「新建会话」/「设置」点击、滚动、hover 全部正常。

## 需求 2：logo 与左上角红绿灯（关闭/最小化）重叠

**现状**：macOS 下 `createMainWindow()` 用 `titleBarStyle:'hiddenInset'` + `trafficLightPosition:{x:16,y:18}`（`src/main.ts` 第 147、156 行），窗口内容满铺到红绿灯下方；侧边栏 wordmark（logo）从 y=0 起 → 与红绿灯重叠。

**方案 A（推荐，仅桌面壳）**：在注入 CSS 里给侧边栏顶部留出红绿灯高度。红绿灯约占据左上 `x:16..70 / y:18..34`，需要约 44–52px 的顶部避让。

```css
/* 仅 macOS 桌面态：侧边栏顶部为红绿灯让位 */
@media (prefers-color-scheme: no-preference), (prefers-color-scheme: light) { } /* 占位，见下 */

body[data-dsh-desktop="darwin"] [data-slot="sidebar"] { padding-top: 52px; }
```

> 若前端没有 `data-dsh-desktop` 标记，可二选一：a) 桌面壳再注入一个 `<style>` 并加一个 `document.documentElement.dataset` 标记；b) 直接在注入 CSS 里用 `:root[class]` 不区分平台、但只在 macOS 分支注入（`insertCSS` 调用处已有 `process.platform` 可判断）。**推荐做法**：在 `createMainWindow` 里按 `process.platform === 'darwin'` 决定是否注入这段 padding CSS，最省事且无浏览器误伤。

**方案 B（备选）**：调 `trafficLightPosition` 下移 + 给 wordmark 容器加对应内边距；或改 `titleBarStyle:'hidden'` 自绘。复杂度更高，不推荐。

**注意/风险**：
1. 选择器要精确命中「wordmark 那一行」，而不是把整个侧边栏（含会话列表）往下推。用 DevTools 定位 wordmark 容器的真实 `data-slot`/class 后微调。
2. `vibrancy:'sidebar'` 下侧边栏是毛玻璃透明背景，新 padding 区域需能正确吸色（保持背景一致）。
3. 仅 macOS 需要；Windows 用 `titleBarOverlay` 已在左上角有自己的控制区，不要误加。

**验收**：logo 与红绿灯不再重叠，红绿灯可正常点击，侧边栏视觉不破相。

## 需求 3：header 右上角显示「本会话 token / 费用 + DeepSeek API 余额」

**目标位置**：`conversation.session.header.utilities` 插槽（`list`、右对齐；「Session log」按钮已在此插槽，契约见 `@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts`）。

**数据来源**：
1. **Token**：已有，直接用。`@deepseek-ai/dsh-token-meter` 注册投影单元 `tokenUsage`（字段 `uncachedInputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens`），经 `session.history` 尾部 `projections` 块 + `session/projection` 推送帧下发；客户端从会话 store 读该投影。
2. **费用**：现成没有。用可配置价格表计算：
   `cost = uncachedInputTokens×P_in + cacheReadTokens×P_cacheHit + outputTokens×P_out`
   - DeepSeek 适配器不报 `cacheWrite`（恒 0）；reasoning 按 output 计。
   - 价格表必须**可配置**（settings / 插件配置），默认填 DeepSeek 当前官网价，不要写死进 UI 代码。
3. **余额**：DeepSeek 官方端点 `GET https://api.deepseek.com/user/balance`，Header `Authorization: Bearer $DEEPSEEK_API_KEY`，返回形如
   `{ is_available, balance_infos:[{ currency, total_balance, granted_balance, topped_up_balance }] }`（以最新官方文档为准）。
   - **必须在 host 侧代理**：API key 只存在于 `~/.dsh/.credentials.yaml`（浏览器读不到），不能下发到前端。

**实现形态（推荐：一个 host+client 插件包，直接照抄 `dsh-plugin-vision` 的结构）**：
- `package.json` 里 `dsh.bundle.patch` + `dsh.client` 声明（`platform:"web"`、`inject` 含 `@deepseek-ai/dsh-client-runtime`）。
- **host half**：`inject: ['credentials','webServer','settings', …]`；用 `ctx.credentials.resolve('DEEPSEEK_API_KEY')` 取 key；注册路由（如 `GET /usage/balance`）转发到 DeepSeek `/user/balance` 并回 JSON；同一插件可提供价格表配置命名空间。
- **client half**：注册 `conversation.session.header.utilities` 插槽，渲染一个小 chip（`tokens · 费用 · 余额`）：tokenUsage 读投影、费用按价格表算、余额 `fetch` 宿主路由（可「点击刷新」+ 失败静默/提示）。

**注意/风险**：
1. `tokenUsage` 是**整段会话日志**口径（含被压缩前的历史、含失败重试的输入），不是「当前可见上下文」；展示时如实标注，避免被当成精确计费单。
2. 余额请求要复用 DSH 凭据 seam，绝不把 key 或请求带进浏览器端代码；余额数值仅显示，不落日志。
3. 费用=估算（依赖价格表与 token 口径），UI 应体现「约/估算」语义；模型切换后价格表要跟着变。
4. 需重启（桌面 App 退出重开）后插件/改动才生效。

**验收**：header 右上角稳定显示本会话输入/输出 token 与估算费用、DeepSeek 账户总余额；无 key 时报「未配置」而不是报错；浏览器直访 `dsh web` 时同样可用（不依赖桌面壳）。
