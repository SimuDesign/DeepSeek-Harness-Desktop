# DeepSeek Harness macOS 桌面客户端 开发计划书

> 本计划基于对官方 `deepseek-ai/deepseek-harness`（npm `@deepseek-ai/dsh@0.1.0-rc.6`）与社区参考实现 `anywhere-labs/deepseek-harness-desktop`（MIT）、`dawangcoding/ClawUI`、`Comfy-Org/desktop` 的源码调研编写。

## 1. 目标与成功标准

**目标**：做一个 macOS 桌面客户端（Electron），内嵌 DeepSeek Harness。用户双击 App 即启动、直接使用 Harness Web UI，无需手动执行 `dsh web`、无需安装 Node.js/pnpm。

**成功标准（验收）**：
- [ ] 双击 `.app` 后 ≤10s 内出现 Harness Web UI（首次启动含 profile 初始化），无需任何命令行操作
- [ ] 客户端复用 `~/.dsh`：能看到现有会话、设置、插件，与 `dsh web` 网页版状态互通
- [ ] 关闭窗口 → 应用隐藏到托盘，Host 继续运行；托盘恢复窗口；"退出" → Host 优雅停止（SIGTERM，≤5s）
- [ ] 打包后的 App 不依赖系统安装的 Node/pnpm/dsh（用 Electron 内置 Node 跑打包进 App 的 dsh）
- [ ] 单实例锁：重复打开只聚焦已有窗口
- [ ] Host 崩溃不静默：显示错误对话框（含输出日志尾部）
- [ ] 生成未签名可用的 DMG 与（凭据齐全时）签名+公证 DMG
- [ ] 核心模块（host-supervisor、window-lifecycle、readiness parser）有单元测试且全绿

## 3. 架构设计

### 3.1 总体架构

```
┌─────────────────────────── macOS App（Electron）──────────────────────────┐
│  主进程 main.ts                                                           │
│   ├─ HostSupervisor（host-supervisor.ts）──spawn──▶ 子进程：              │
│   │     Electron-as-Node + 打包的 @deepseek-ai/dsh                        │
│   │     `dsh web --host 127.0.0.1 --port 0`  ◀── stdout 就绪行握手        │
│   │     `dsh web: http://127.0.0.1:<随机端口>`                             │
│   ├─ WindowLifecycle（window-lifecycle.ts）：窗口 + 托盘 + 退出状态机       │
│   └─ BrowserWindow ──loadURL(origin + ?dsh-desktop-platform=darwin)──▶    │
│         Harness Web UI（由 Host 提供，含 window.__DSH_BOOT__ 引导）        │
│   数据：$DSH_HOME = ~/.dsh（与 CLI 共享 sessions/settings/storages）       │
└───────────────────────────────────────────────────────────────────────────┘
```

不改动 Harness 任何源码：桌面端只是一个"监管器 + 浏览器壳"，渲染层与 Host 协议不变（未来官方若提供 IPC carrier 可无缝替换，社区参考的"已知限制"一节同样适用）。

### 3.2 官方 CLI 关键契约（实现必须遵守）

- 默认 `http://127.0.0.1:3080`；`--port 0` → 系统分配空闲端口（**避免端口冲突**）；`--host 0.0.0.0` 官方故意不支持
- 启动后 stdout 打印就绪行：`dsh web: http://127.0.0.1:<实际端口>`（可能附 ` (LAN: ...)`）
- SIGTERM → 优雅卸载（≤5s，退出码 0）；SIGINT → 130；第二个信号强制退出
- web/headless profile 首次使用自动从内置模板初始化；`$DSH_HOME/profiles/node_modules` 符号链接兜底每次启动自愈
- `/api` 有浏览器信任围栏，回环 IP 字面量 Host 自动受信（我们走 `127.0.0.1` 即可）

### 3.3 关键架构决策（ADR 摘要）

- **ADR-1 子进程监管而非进程内嵌入**：Electron 主进程进程内跑 cordis 树会与 dsh 的进程级假设（SIGTERM、env 分层、`--expose-internals`、node:sqlite 等）冲突，且每次官方更新都要重新适配。子进程方案对官方改动零侵入，采纳社区参考同款方案。
- **ADR-2 Electron（已确认）**：有直接参考实现；`ELECTRON_RUN_AS_NODE=1` 使打包后无需携带第二个 Node。要求 Electron 内置 Node ≥22.5（node:sqlite 需要）；参考实现用 Electron 43.4.0，实施时锁定并验证。
- **ADR-3 端口与就绪握手**：`--port 0` + 解析就绪行。就绪行是官方 CLI 的稳定输出契约；解析器做严格校验（http、host ∈ {127.0.0.1, localhost}、显式端口、path=/、无 query/hash），冲突行即失败。
- **ADR-4 共用 `~/.dsh`（已确认）**：状态互通是产品诉求；profile 符号链接自愈机制使 App 升级不会留下坏链接。
- **ADR-5 完全自包含打包**：打包时用 pnpm 把 `@deepseek-ai/dsh`（固定版本）的完整依赖闭包物化（materialize pnpm 符号链接为真实文件）进 `resources/host/`；运行期永远用自带的 dsh，绝不回落到 PATH 里的 dsh，杜绝版本漂移。
- **ADR-6 安全硬化**：`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、拒绝全部权限请求、导航锁定 host origin、外链走系统浏览器（`shell.openExternal`）。

## 6. 边界情况与失败模式

| 场景 | 行为 |
|---|---|
| Host 产物缺失/损坏 | `assertHostArtifacts` 抛错 → 错误对话框 → 退出 |
| 就绪前退出（Node 不兼容等） | reject 并附 32KB 输出尾部 |
| 就绪超时（90s） | SIGTERM → 报错含输出尾部 |
| 就绪后意外崩溃 | `onUnexpectedExit` → 错误对话框（日志尾部）→ 退出（v1） |
| 退出时 Host 卡死 | SIGTERM 后 5s 未退 → SIGKILL |
| 端口冲突 | `--port 0` 系统分配，天然规避 |
| 双开 | 单实例锁，第二个实例聚焦已有窗口 |
| 启动中退出 | `bootQuitPromise` 合并退出路径，不悬挂 |
| macOS 睡眠/唤醒 | 子进程持续运行，无特殊处理（验收确认） |
| GUI 启动无 shell 环境 | 凭据读取顺序含 `~/.dsh/.credentials.yaml`（可在 UI 设置中配置），README 说明；env 注入留后续版本 |
| App 升级后 profile 链接 | `$DSH_HOME/profiles/node_modules` 每次启动自愈 |
| 首次启动无网络 | profile 从内置模板初始化（不需要 npm 网络）；`~/.dsh` 已有则直接复用 |

## 7. 测试策略与验收

- **单元测试（vitest，node 环境，mock child_process）**：任务 1/2/3/4 的全部行为 + 打包配置断言
- **脚本冒烟**：stage-runtime 后直接运行打包出的 dsh 验证就绪行（不依赖 GUI）
- **手动验收清单**：§1 成功标准逐项 + 托盘图标深/浅色、外链跳系统浏览器、CORS/导航锁定生效、与 `dsh web` 同时运行时各自端口独立
- **范围外（后续版本）**：Playwright E2E（官方 apps/web 已有 playwright 基建可复用）、`electron-updater` 自动更新、Windows/Linux 包、托盘崩溃重启按钮、env 凭据注入

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Electron 内置 Node 与 dsh 的 Node 要求不匹配（node:sqlite 需 ≥22.5） | 任务 3/5 的冒烟步骤直接在 ELECTRON_RUN_AS_NODE 下验证就绪行；不匹配则换 Electron 版本 |
| pnpm 符号链接导致打包缺失 | stage 物化步骤 + afterPack 校验 + 打包后运行验收，三重拦截 |
| dsh rc 版本 API 漂移（就绪行格式、flag） | 精确锁定版本；升级走显式 bump + 全量测试；就绪行解析器对格式变化 fail-loud |
| 公证/签名门槛 | 本地未签名路径可用；签名路径文档化，凭据由用户提供 |
| 社区参考实现的 rc 状态 | 只移植已验证的 supervisor/打包模式，自写全部代码并配测试 |
